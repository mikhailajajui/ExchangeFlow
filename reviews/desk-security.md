# Branch desk: security review

| Date 2026-10-12 | Scope: `exchangeflow/apps/teller-lite/` (server, page, rules file, tests) against `apps/api/src/http.ts` and `packages/adapter-rates/src/uexchange.ts` | Sources read: all `src/server/*`, `src/shared.ts`, `src/web/App.tsx`, `api.ts`, `format.ts`, `index.html`, `vite.config.ts`, `rules/*`, `package.json`, plus `workflow-core` `request.ts` and `quote.ts` |

Written by the security-reviewer agent (no write tool); saved verbatim by the main session. DESK-SEC-03 re-verified by the main session (`quoteCurrencyFor('constructor','CAD')` returns `'constructor'`).

## Headline findings
- **The record is not evidence, and the desk cannot detect shopping.** The server keeps nothing. The printed record has an unkeyed, recomputable fingerprint and a random record number nobody can verify. A teller can edit the page and then print it. A teller can also re-run the check with different amounts, payment methods or branches, or split a request, and head office never sees the attempts. (DESK-SEC-01)
- **If `EFL_HOST` is set to a LAN address, the desk becomes an unauthenticated, plain-HTTP service that handles member names.** Anyone on the network can use it and produce "official" looking records. Nothing stops this setting today. (DESK-SEC-02)
- **Prototype-key bug.** `MINOR_UNITS['constructor']` and `RATE_FEED_IDS['constructor']` are truthy, and `quoteCurrencyFor('constructor','CAD')` returns `'constructor'`. A caller can therefore force an uncached download of the 2 MB uexchange.ca feed on every `/api/check` call, which has no limiter. Each failed download is also never cached. This is an amplification and DoS path to the upstream feed. (DESK-SEC-03)
- **Rate isolation is good.** `buildContext(values, branch, asOf)` receives no rate, and the rate is used only for display. The same-origin check, body cap, CSP and path-traversal guard are sound for loopback. Remaining gaps: no Host allow-list (DNS rebinding), and an unhandled stream error that can crash the process.
- **Rules-file integrity rests on file permissions alone.** `status: APPROVED` and `approvedBy` are self-asserted text, and reloads are keyed on mtime. (DESK-SEC-04)
